# bureau-kata.com

The Kata website (CI V3.0): a static site plus one serverless function, deployed by Vercel from the `kata-2-0` branch.

## What lives where

| Path | What it is | Edit it? |
|---|---|---|
| `src/kata.html` | The design source: every page, all styles and all scripts in one file. Most copy sits in the HTML. The lists (services, founders, network, the seven principles, the Index) are arrays in the script near the bottom. | **Yes, this is where changes happen** |
| `src/assets/` | The images the site uses, plus the vector mark (`mark.svg`, `tagline.svg`). | Yes |
| `src/legal.json` | Impressum and Datenschutz details. `src/legal_pages.py` turns them into `/imprint` and `/privacy`. | Yes |
| `src/fonts/`, `src/static/` | Self-hosted fonts; favicons and the share card (`src/gen_static.py` regenerates them). | Rarely |
| `src/build.py` | Builds `src/` into `site/` and `vercel.json`. | Only to change how the site is built |
| `site/` | Everything that is served. Generated by the build. | **Never by hand** |
| `vercel.json` | Serving rules: only `site/` is served, no framework, install or build step, old URLs (`/services`, `/team` …) land on the right page, caching and security headers. Generated by the build. | **Never by hand** (change it in `build.py`) |
| `api/enquiry.js` | `POST /api/enquiry`, the contact form. Writes the enquiry to Attio (person, note, a 24h task) and sends the auto-reply and the internal notification through Resend. | Yes, directly |

`APPROACH.md`, `BRIEFING*.md` and `HANDOFF.md` describe the previous Next.js site.

## Changing the site

1. **Edit `src/`**, never `site/`.
2. **Build:** `python3 src/build.py` regenerates `site/` and `vercel.json`. Python 3.8 or newer, no packages needed.
3. **Preview:** `python3 src/serve.py 8000`, then open http://localhost:8000. It behaves like Vercel (clean URLs, rewrites). The contact form does not run locally.
4. **Commit the source and the output together:** `git add src site vercel.json api && git commit -m "Site: <what changed>"`
5. **Push:**
   - Straight to live: `git push origin kata-2-0`. Vercel deploys production in about a minute; hard-refresh to beat the browser cache.
   - With a preview first (for anything non-trivial): `git checkout -b edit/<name> kata-2-0`, commit, `git push -u origin edit/<name>`. Vercel builds a preview URL. When it looks right: `git checkout kata-2-0 && git merge --ff-only edit/<name> && git push origin kata-2-0`.

## Who does what

- **Claude Code on the Mac** can run the whole loop, including the push.
- **Cowork** (Claude in the cloud) can edit, build, preview and commit onto the branch in `~/katamedia`, but has no GitHub login. The push always happens from the Mac.
- **The prototype on claude.ai** is a review copy of `src/kata.html`, not the source.

## Guardrails

- Never edit `site/` or `vercel.json` by hand: the next build overwrites them.
- No em-dashes (—) in visible copy. Use a colon, comma or full stop. Page titles and screen-reader labels ("Kata — …") are the only exception.
- The Impressum is placeholder text by decision, and the build warns about it on every run. Replace the values in `src/legal.json` once the details are settled, then have them reviewed.
- `api/enquiry.js` reads its keys at runtime: after changing them in Vercel, redeploy. If the keys are missing, the form tells visitors to email hello@bureau-kata.com.
- Don't touch DNS or MX at the registrar: MX `smtp.google.com` is the live Google Workspace email.
- One-time checks in Vercel: Settings → Git → Production Branch is `kata-2-0`, and Settings → Environment Variables has `ATTIO_API_KEY` and `RESEND_API_KEY` enabled for Production.

## Rollback

Vercel → Deployments → pick an earlier deployment → Promote to Production. The previous Next.js site is in the history up to `b52a1d0` (branch `main`).
